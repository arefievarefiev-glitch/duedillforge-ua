# Протокол циклу `next → дія → report`

`ddf` = `${CLAUDE_PLUGIN_ROOT}/scripts/ddf` (у Windows без POSIX-оболонки `${CLAUDE_PLUGIN_ROOT}/scripts/ddf.cmd`). Усі відповіді — JSON. Якщо завдань кілька, став `--task <task_id>` перед командою (`ddf --task <id> next`); без нього береться останнє незавершене.

## Цикл

Виклич `ddf next`. Дій за полем `action`, потім знову `ddf next`, окрім випадків, де сказано завершити хід.

### `action: dispatch` — агенти

У відповіді `slots[]`. **Усі `Agent`-виклики роби в одному повідомленні** (інакше агенти виконуються по черзі й перевірка триває на години довше). Для кожного слота передай без змін: `subagent_type` = `agent`, `description`, `prompt`; якщо є `model`, передай і його. Нічого не додавай до `prompt`.

Коли агент завершив, одразу виклич для нього `ddf report --slot <slot_id>`. Відповідь:
- `status: done` — прийнято;
- `status: open` — результат відхилено (`message` каже чому); нічого не виправляй руками, після `ddf next` слот видасться знову з поясненням;
- `status: failed` — слот не вдався після кількох спроб; перевірка триває без нього;
- `status: paused` — протермінований вхід у NotebookLM. Завершувати хід не треба, поки не опрацьовано решту слотів хвилі.

Опрацювавши всі слоти хвилі, виклич `ddf next`.

### `action: gate` — рішення людини

Надрукуй `text` дослівно (це таблиця готовності або список критичних знахідок). Потім `AskUserQuestion` з варіантами з `decisions` (`proceed` — «Продовжити», `rescan` — «Я доповнив блокнот, перевір ще раз», `cancel` — «Скасувати»). Відповідь передай: `ddf gate --decision <варіант>`. Потім `ddf next`.

Якщо користувач на шлюзі готовності хоче задати вид документа чи змінити рівень знахідки: `ddf docs set-kind --doc <id> --kind <вид>` або `ddf finding override <id> --severity <critical|significant|info> --note "…"` (critical — критичний, significant — суттєвий, info — до відома), і повтори шлюз (`ddf next`).

Якщо `AskUserQuestion` недоступний, надрукуй `text` разом із трьома варіантами відповіді й заверши хід: відповідь прийде через `/duedillforge:continue`.

### `action: pause`

Надрукуй `message` дослівно й заверши хід. Продовження — `/duedillforge:continue` (скіл викличе `refresh_auth` і `ddf resume`).

### `action: done`

У відповіді `outputs` (шляхи файлів) і `warnings`, `degraded`. Покажи користувачеві файли (`present_files`, якщо є; інакше `SendUserFile` для кожного .docx і .xlsx; а за наявності підключеної теки на комп'ютері користувача скопіюй туди теку з рядка «копію збережено»). Потім коротко: скільки знахідок за рівнями (`ddf status`), що лишилося непідтвердженим, перелік `degraded`, якщо він не порожній. Поради про наступні кроки: перегляд критичних знахідок; запит документів продавцю (файл «Запит_документів»). Заверши хід.

### `action: failed` / `cancelled`

Надрукуй `message` і заверши хід.

## Збої

- `ddf` повернув JSON з полем `error` — це не крок, а помилка виклику. Повтори ту саму команду один раз. Якщо помилка лишилась, надрукуй її й заверши хід.
- Агент не повернув нічого — все одно `ddf report --slot …`: програма сама повторить спробу або деградує слот.
- Скасування користувачем: `ddf task cancel`, далі `ddf next` покаже `cancelled`.

## Інструменти

`Bash` — для `ddf`. Файли, названі в відповідях `ddf`, можеш читати. Файли в `texts/`, `ledger/`, `state.json`, `register.json` не читай і не редагуй, власних агентів не запускай.
