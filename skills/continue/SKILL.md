# duedillforge / continue

Прочитай `skills/dd/references/router.md`: цикл той самий. Тут лише те, що відрізняє продовження.

## Визнач завдання

`ddf task resolve` (або `ddf --task <id> task resolve`, якщо користувач назвав завдання). Потім `ddf status`: подивись `pause`, `open_gate`, `terminal`.

## Що робити

1. **Пауза через вхід** (`pause.reason` = `auth_expired`). Спитай, чи користувач виконав `nlm login`. Якщо так: викликай `refresh_auth` (інструмент notebooklm-mcp), а потім `notebook_get` для будь-якого блокнота завдання, щоб переконатися, що вхід працює. Лише тоді `ddf resume` і цикл. Не працює — скажи про це й заверши хід; не переходь на вебпошук.
2. **Відкритий шлюз** (`open_gate`). Якщо `$ARGUMENTS` містить відповідь, зіставляй: «далі», «продовжити», «ок» → `proceed`; «доповнив», «додав у блокнот», «перевір ще раз» → `rescan`; «скасувати» → `cancel`. Не зрозуміло — `AskUserQuestion` з варіантами шлюзу. Далі `ddf gate --decision …` і цикл.
3. **Завершене завдання** (`terminal.status` = `done`), користувач просить змінити рівень знахідки чи додати примітку: `ddf finding override <id> --severity <critical|significant|info> --note "…"`, потім `ddf export`; покажи оновлені файли. Нову перевірку не запускай.
4. **Нічого з переліченого.** Якщо завдання не на паузі, без шлюзу й не завершене, виклич `ddf next` і працюй за циклом.

Якщо `ddf task resolve` каже, що завдань немає, поверни користувача до `/duedillforge:dd`.
